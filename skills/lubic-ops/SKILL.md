# lubic 日常运维

用户多半没有编程经验。命令替用户跑，用大白话说明每一步做了什么、结果是什么意思。

具体命令以仓库里 [`docs/deploy.md`](../../docs/deploy.md) 的「5. 日常操作」和各部署章节为准，开始前先读这两部分。

## 1. 找到总控

先确认总控跑在哪、怎么部署的，后面所有命令都依赖它：

- 在哪台机器：本机，还是要 SSH 到云服务器。
- 部署方式：Docker（找 `docker-compose.yml` 所在目录，`docker compose ps` 能看到 `controller`）还是 Mac 原生（`launchctl list | grep lubic`）。

完成标准：能拼出一条可用的 `lubic-controller -c <配置> <子命令>` 前缀，并用 `--help` 跑通一次。

## 2. 按用户的事情处理

- **取回原片**：用 `upos` 按房间名和开播时间查，比如「主播A 2026-11-01 13:04」。查不到时先确认是否超过 5 天。`curl` 在用户想存文件的机器上跑，下完逐个核对字节数。命令里带凭证：只在终端里跑，不要整段复述给用户、不要写进任何文件或日志。
- **手动场末**：`end <房间名>`，之后到控制台「投稿」看这份稿件进入待投。
- **需人工（attention）**：先让用户去 B 站创作中心确认稿件到底投上没有，再按文档三选一处理。改库前停总控、改完启动；`UPDATE` 前先 `SELECT` 给用户看要改的那一行，确认后再改。
- **暂停房间、更新、看日志**：照文档做。排查问题时先看最近的日志，用一两句话说出原因，再提修法。

## 3. 动手前确认

会改变状态的操作（停 / 启服务、改库、更新、丢弃稿件）先说清楚要做什么、会有什么影响，用户同意后再执行。只读的查询（`upos`、看日志、`SELECT`）可以直接做。

完成标准：用户的事情办完，并告诉用户结果（文件存在哪、稿件现在是什么状态、问题的原因），以及下次遇到同样的事可以怎么说。
