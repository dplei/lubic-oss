# 部署 lubic

用户多半没有编程经验。你是向导：用大白话解释每一步在做什么，命令替用户跑，用户只做只有他能做的事。

所有具体命令、配置格式、compose 与 plist 模板以仓库里的 [`docs/deploy.md`](../../docs/deploy.md) 为准，先完整读一遍再开始；本文件只规定流程。

## 1. 问场景

依次问清下面几件事，每次只问一两个，给出选项和你的推荐：

- 录像在哪台机器上录：自己的 Windows 电脑、自己的 Mac、云服务器，还是云服务器加家里电脑一起（混合多机）。
- 同时大概录几个房间。按每个房间约 10 Mbps 下行 + 10 Mbps 上行、每小时 4～5 GB 估算，告诉用户他的网络和磁盘够不够；家用宽带上行常只有 30～50 Mbps，录两路以上就会挤占家里上网。
- 机器能否一直开着。家用电脑要关掉自动睡眠。
- 部署在云服务器时：有没有域名。没有域名只能用 SSH 隧道看控制台，也不能做混合多机。

完成标准：能说出一句「你的方案是：……」，包含每台机器跑什么（总控 / Agent / 两者）、用 Docker 还是 Mac 原生、控制台怎么打开，用户确认同意。

## 2. 检查环境

在要部署的每台机器上检查，缺什么告诉用户为什么需要、怎么装：

- Windows：Docker Desktop 已安装并在运行（`docker version` 有 Server 段），设置里开了开机启动。
- Linux 服务器：`docker compose version` 可用；CPU 是 x86_64（`uname -m`）。ARM 机器要按 `docs/deploy.md` 自建镜像，提醒用户十几分钟、要 4 GB 以上内存。
- Mac：`xcode-select -p`、`cargo --version`；可用磁盘空间（`df -h`）。
- 云服务器有域名时：域名已解析到这台服务器的 IP（`dig +short` 或 `nslookup`），80、443 端口在安全组放行。

完成标准：每台机器的每一项都确认可用，或者用户明确知道还差什么。

## 3. 生成配置

按 `docs/deploy.md` 对应章节，在运行目录写好 compose / Caddyfile / `controller.toml` / `agent.toml` / plist。写之前把运行目录路径告诉用户；目录已存在时先列出里面有什么，不覆盖已有文件，除非用户同意。

完成标准：每个文件写完后给用户看一眼内容，并用一句话说明它是干什么的。暂时拿不到的值（密码哈希、token）留成占位符，到第 4 步再填。

## 4. 逐步执行

一次一步：先说明这一步要做什么、会改动什么，用户同意后再执行，执行后检查结果再进下一步。顺序：

1. 拉镜像或编译。
2. 生成控制台密码哈希：命令交给用户自己在终端里运行并输入密码，密码不要经过你；用户把输出的哈希贴给你或自己填进 `controller.toml`。
3. 启动总控，确认控制台能打开（有域名的还要确认 HTTPS 证书已签发）。
4. 让用户在控制台「机器」里新增机器，拿到 token。token 由用户填进 `agent.toml`，或者用户贴给你后由你填写。混合多机时每台录制机各一个 token。
5. 启动每台 Agent，确认控制台里这台机器显示在线。
6. 引导用户在控制台里扫码添加投稿账号、建投稿模板、添加房间（`docs/deploy.md` 第 4 节）。

出错时先看日志（Docker：`docker compose logs --tail 100 <服务>`；Mac：`~/Library/Logs/lubic/`），用大白话告诉用户原因，再提出修法。

完成标准：控制台里每台机器在线、至少一个账号和一个房间已添加。最后告诉用户：控制台地址、配置和录像放在哪、怎么更新（`docs/deploy.md` 的更新小节）、出问题看哪里的日志。
